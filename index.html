On Building Software That Stays Out of the Way

Chakradhar Reddy1

1 Even Healthcare, Bengaluru, India. Previously Zomato. Correspondence: chakridevireddy69@gmail.com

Abstract. I'm a software engineer who cares about clean interfaces, strong systems, and building things that feel good to use. I believe simplicity is the ultimate sophistication. From backend engineering to user experience, I try to create software that stays out of the way and quietly does its job well, but stands out when it needs to. This document surveys five deployments of that idea in industry, five more at home, and the tools involved.

Keywords: full-stack development, system design, user experience, open to interesting work

3 Selected Work

The following were built outside working hours, mostly to find out how something actually works. A complete survey is available in the catalogue [6].

3.1 Life Sim [1]

TypeScript, Vite, Canvas

A configurable cellular-automaton playground that pushes Conway's Game of Life way past the basics: totalistic rules, an agent-based ecosystem, Gray-Scott reaction-diffusion, and custom per-cell JS. Typed-array sim loops, a pan/zoom canvas, and whole universes encoded into shareable URLs, all in ~17KB gzipped.

3.2 CodeCollab [2]

Next.js, WebRTC, JavaScript

A real-time collaborative IDE, built to see how far live editing could be pushed. Next.js, WebSockets and CRDTs, with 20+ users syncing without stepping on each other.

3.3 get-proctored.ai [3]

Python, TensorFlow, MediaPipe

An AI-powered exam proctoring system using TensorFlow and MediaPipe. Reduced false positives by ~30% with smarter rules and real-time face and eye tracking. Started as a uni project, ended up actually being used by professors.

3.4 Node Utils [4]

TypeScript, Node.js

A playground for low-level Node.js: worker-thread abstractions for real multithreading, geohashes, semaphores, and other things built to find out how they actually work.

3.5 Pixel Drawing Simulator [5]

TypeScript, Canvas, Webpack

An interactive canvas tool for exploring pixel-level algorithms like Bresenham and flood-fill. Built to see how they behave on a real machine, not just on paper.

II. Works

Reddy’s minor works were produced outside working hours, chiefly to discover how a thing actually works. The principal examples follow.

Life Sim (TypeScript, Vite, Canvas). Conway's Game of Life pushed way past the basics: totalistic rules, an agent-based ecosystem, Gray-Scott reaction-diffusion, custom per-cell JS, and whole universes in shareable URLs. ~17KB gzipped.

CodeCollab (Next.js, WebRTC, JavaScript). A real-time collaborative IDE, built to see how far live editing could be pushed. WebSockets and CRDTs, 20+ users syncing without stepping on each other.

get-proctored.ai (Python, TensorFlow, MediaPipe). AI exam proctoring with real-time face and eye tracking, ~30% fewer false positives. Started as a uni project, ended up actually being used by professors.

Node Utils (TypeScript, Node.js). Low-level Node.js: worker-thread abstractions for real multithreading, geohashes, semaphores, and other things built to find out how they actually work.

Pixel Drawing Simulator (TypeScript, Canvas, Webpack). Bresenham, flood-fill and friends on an interactive canvas. Built to see how they behave on a real machine, not just on paper.
